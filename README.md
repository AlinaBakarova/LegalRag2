# Legal AI Workspace

Локальное однопользовательское приложение для будущей работы с юридическими
документами. Реализованы **этапы 1–2**: интерфейс NiceGUI/FastAPI, постоянное состояние
SQLite, миграции и отдельный worker с сохраняемой очередью заданий.

Доступны загрузка TXT/PDF/DOCX, извлечение текста, просмотр оригиналов и удаление
пользовательских документов. Поиск, LLM и юридический анализ пока не реализованы.
Приложение не обращается к облачной LLM.

## Установка и запуск

Нужны Python 3.12 или 3.13 и `uv`. Команды выполняются из корня репозитория.
В облачной среде используйте существующий checkout: отдельный Git worktree не нужен.

```bash
uv sync --locked
test -f .env || cp .env.example .env
```

В `.env` задайте `LEGAL_WORKSPACE_DATA_DIR` — абсолютный путь к постоянному каталогу
данных **вне репозитория**, доступному для записи. В примере используется
`/workspace/legal-workspace-data`; на своём компьютере замените путь.
Если переменная не задана, используется `~/.local/share/legal-workspace`.
Не перезаписывайте уже существующий `.env` с собственными настройками.

```bash
uv run --locked legal-workspace init
uv run --locked legal-workspace serve
```

В **другом терминале**, из того же каталога и с тем же `.env`:

```bash
uv run --locked legal-workspace worker
```

Веб-приложение слушает локальный адрес `127.0.0.1`, порт `8080` по умолчанию.
Оба процесса также автоматически применяют недостающие миграции при запуске.
`Ctrl+C` или `SIGTERM` корректно останавливают процесс. Worker завершает текущий
обработчик перед остановкой. Постоянные файлы сохраняются, процессы после
перезапуска машины нужно запустить заново.

Авторизация для удалённого/многопользовательского доступа в этапе 1 не предусмотрена;
настройка внешнего адреса прослушивания отклоняется.

## Как проверить работу

1. Запустите веб-приложение и один worker в разных терминалах.
2. Загрузите документ в «Мои документы». Во время обработки виден небольшой индикатор.
3. После успешной обработки остаётся только название; щелчок открывает карточку
   со ссылками на оригинал. Извлечённый текст в интерфейсе не показывается.
4. При ошибке видно «Не удалось обработать документ», при неполном извлечении —
   «Часть документа не удалось прочитать». Подробности доступны в логах worker.
5. Наведите курсор на замок/перо у разделов и на корзину: появятся подсказки.
6. Удалите пользовательский документ корзиной и подтвердите. Проверьте, что файл
   исчез; после перезапуска он также не должен появиться.

Техническая кнопка проверки worker и журнал заданий убраны с главного экрана.
Диагностика остаётся через CLI/API:

```bash
uv run --locked legal-workspace check
```

Команда создаёт задание `PRAGMA quick_check` и выводит ID. Наличие worker и состояние
этого задания можно проверить через локальный HTTP API:

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/health` | Доступность веб-приложения и хранилища |
| `GET /api/status` | Присутствие worker и счётчики заданий |
| `POST /api/jobs/check` | Поставить диагностическое задание |
| `GET /api/jobs` | Последние 20 заданий |
| `GET /api/jobs/{id}` | Состояние и результат задания |
| `GET /api/docs` | Документация API |

`/api/health` проверяет веб-приложение и БД, присутствие worker — `/api/status`.
Диагностика не является проверкой юридического содержания документов.

## Очередь и восстановление

- Состояния: `queued → running → succeeded/failed`.
- Захват задания атомарен (`BEGIN IMMEDIATE`); у каждого захвата уникальный токен аренды.
- Отдельный heartbeat продлевает аренду во время выполнения обработчика.
- Новый worker возвращает задание с истёкшей арендой в очередь. По умолчанию
  допускается не более трёх попыток, включая восстановление после аварии.
- Устаревший обработчик не может сохранить результат после потери аренды.
- Ошибки обработчика повторяются с ограниченной задержкой; неизвестный тип задания
  завершается ошибкой без повторов. В БД сохраняется безопасный код ошибки.
- Доставка **как минимум один раз**: будущие обработчики должны быть идемпотентными.
  Протокол аренды предотвращает устаревшую запись результата, но сам по себе не
  предотвращает повторный внешний вызов или другой побочный эффект.

Веб-процесс и worker используют одну SQLite-БД в режиме WAL. Миграции защищены
межпроцессной файловой блокировкой. Размещайте данные на локальной файловой системе,
не на сетевом диске. Схема хранится в пакете `persistence/migrations`, поэтому
миграции доступны и в собранном wheel.

## Тесты и проверки

```bash
uv run --locked ruff check src tests
uv run --locked ruff format --check src tests
uv run --locked pytest -q
```

Обычный запуск включает реальные отдельные процессы веб-приложения и worker:
перезапуск, сохранность задания, принудительное завершение worker, продление аренды
и восстановление. Тесты используют временные каталоги и не меняют рабочие данные.

Браузерный тест использует установленный Chromium. При необходимости укажите путь
в `LEGAL_WORKSPACE_CHROMIUM`; по умолчанию исполняемый файл ищется как `chromium`.
Браузер автоматически не скачивается.

```bash
uv run --locked pytest -q --browser
```

Он проверяет подсказки значков, загрузку TXT, индикатор обработки, отсутствие
извлечённого текста и технического журнала, удаление, понятные ошибки и узкий экран.
Без `--browser` этот один тест явно пропускается.

## Структура

```text
src/legal_workspace/
  main.py                 CLI и сборка веб-приложения
  config.py               проверенные настройки
  api.py                  локальный HTTP API
  services.py             операции рабочей области
  ui/layout.py            Python-интерфейс
  persistence/
    database.py           подключения, WAL, запуск миграций
    models.py             рабочая область, задания, присутствие worker
    migrations/           миграции Alembic
  jobs/
    queue.py              сохранение, захват, аренда, повторы
    worker.py             выполнение и heartbeat
tests/
  unit/                   настройки и безопасные ошибки
  integration/            миграции, очередь, worker, API
  acceptance/             процессы, восстановление, браузер
```

Данные, `.env`, логи проверок и виртуальное окружение не коммитятся. В логах ошибок
приложения выводятся ID и типы ошибок, без payload заданий, значений настроек и
полных исключений SQL/HTTP. Политику для документов и облачного провайдера предстоит
дополнить на соответствующих этапах.

Следующий этап — индексация и гибридный поиск. Он начинается только после
отдельного согласования результатов этапа 2.


## Документы — этап 2

После перехода с ветки этапа 1 выполните `uv sync --locked` и перезапустите веб-процесс
и worker. Существующий каталог данных сохраняйте: миграция `0002_documents`
добавляет таблицы документов и фрагментов, сохраняя рабочую область и задания.

1. Запустите `serve` и `worker` как описано выше.
2. В левой панели загрузите TXT, PDF или DOCX (непустой файл до 25 МБ).
3. Дождитесь исчезновения индикатора обработки. Нажмите на название документа.
4. Откройте оригинал PDF или скачайте исходный файл без изменений.
5. Перезапустите оба процесса: файл и текст должны сохраниться.
6. Нажмите значок корзины у пользовательского документа и подтвердите удаление. Оригинал, извлечённый текст
   и задания обработки будут удалены. Базовые источники удалить нельзя, в том числе через API.

HTTP API документов: `GET/POST /api/documents`, `GET/DELETE /api/documents/{id}`,
`GET /api/documents/{id}/spans`, `GET /api/documents/{id}/original`,
`POST /api/documents/{id}/reprocess`. Параметр `download=false` у оригинала
открывает PDF в браузере; по умолчанию файл скачивается.
POST принимает multipart-поле `file`. Ответ `202` означает сохранение и постановку
на обработку, а не успешное извлечение текста. Без worker файл остаётся в ожидании.

### Форматы и границы обработки

- TXT: UTF-8 (с BOM или без), ориентир — номер исходной строки. Другие кодировки
  отклоняются с сообщением `utf8_required`, файл можно пересохранить и загрузить заново.
- PDF: текст по физическим страницам. Пустые страницы дают предупреждение; файл
  без извлечённого текста также показывает предупреждение. OCR пока отсутствует.
  При неполном извлечении показывается «Часть документа не удалось прочитать».
- DOCX: абзацы и ячейки таблиц в порядке основного текста. Ориентиры — абзац или
  таблица/строка/ячейка, номера страниц не выдумываются. Колонтитулы, сноски,
  вложенные таблицы и другие неподдержанные элементы дают предупреждение.
- Базовый документ: до **300 МБ**, для PDF — до **1000 страниц**.
- Пользовательский документ: до **25 МБ**, для PDF — до **300 страниц**.
  МБ указаны в десятичной системе (1 МБ = 1 000 000 байт). Проверяются оба ограничения.
  Константы находятся в `documents/limits.py`; прежнего ограничения 2 млн символов нет.
- Для DOCX: не более 2000 ZIP-записей; суммарный распакованный размер до 100 МБ
  у пользовательского и до 600 МБ у базового документа.
- Математического парсера нет: обычные текстовые формулы сохраняются как текст.
  Точная реконструкция сложной вёрстки и уравнений не выполняется.
- Успешная обработка означает техническое извлечение текста, а не правовую проверку.
  Определение сканов по отсутствию текста является эвристикой: изображения на странице
  с текстом и сложная вёрстка требуют ручной сверки с оригиналом.

При импорте файлы копируются и хэшируются порциями; комплект не загружается целиком
в оперативную память. PDF читается через файловый поток, фрагменты извлекаются
постранично во временный файл и записываются в SQLite пакетами в одной транзакции.
Сам PDF-парсер всё ещё расходует память на внутренние структуры; использование
файлового потока не гарантирует постоянный объём RAM для любых PDF.

Оригиналы лежат в `DATA_DIR/originals` под внутренними ID, исходные имена не используются
как пути. Фрагменты содержат точный извлечённый текст, его диапазон в каноническом тексте
(соединение фрагментов символом перевода строки) и структурный ориентир. Хэш оригинала
и версия парсера сохраняются. При публикации текста проверяются доступность документа
и действующая аренда задания. Повторное выполнение заменяет фрагменты без дубликатов.

Удаление сначала скрывает документ, затем очищает файл и текст. При старте приложение
завершает прерванные удаления и очищает временные/бесхозные файлы своего каталога
оригиналов. Обработка в полёте не может вернуть удалённый документ. Удаляются также
запись документа, фрагменты и все его задания обработки.
Старые технические отметки удаления предыдущей версии очищаются при старте.
Это не механизм гарантированного стирания SQLite-страниц, диска или резервных копий.

### Базовая библиотека

В репозитории `corpus/manifest.json` содержит пустой список. Свой проверенный комплект
можно импортировать локально; синтетические документы используются только в тестах.
Автоматического скачивания или утверждений об актуальности законодательства нет.

Для импорта подготовьте локальную папку с проверенными файлами и JSON-манифестом:

```json
{
  "documents": [
    {
      "key": "unique-reviewed-source-key",
      "file": "reviewed-document.txt",
      "sha256": "<64 шестнадцатеричных символа SHA-256 файла>",
      "title": "<название проверенного источника>",
      "source_url": "<URL фактического источника>",
      "edition": "<сведения о редакции>",
      "verified_on": "2026-11-17"
    }
  ]
}
```

Это схема заполнения, не готовый нормативный источник. Пути файлов должны быть внутри
папки манифеста. Контрольная сумма проверяется до импорта; URL хранится как метаданные,
по нему ничего не скачивается. Дата отражает вашу проверку, а не автоматическую
юридическую верификацию приложением.

```bash
uv run --locked legal-workspace import-corpus --manifest /absolute/path/manifest.json
```

Worker извлечёт текст обычным способом. Повторный импорт с тем же `key`, содержимым
и метаданными возвращает существующий документ. Изменение содержимого или метаданных
под существующим ключом отклоняется: обновление редакций в этом этапе не реализовано.
Импорт нескольких источников сохраняет успешно добавленные документы при последующей
ошибке; после исправления повторный запуск безопасен.

Новые модули: `documents/parsers.py`, `service.py`, `corpus_import.py`,
`ui/documents.py`, миграция `0002_documents.py`. Тесты форматов используют явно
синтетические документы и не проверяют нормы права.


## Обновление существующей базы этапа 2

Останавливать и обновлять нужно оба процесса (`serve` и `worker`). Удалять SQLite,
оригиналы или заново импортировать всю библиотеку не требуется.

1. Остановите оба процесса и сделайте резервную копию своего каталога данных.
2. Переключитесь на ветку исправлений и выполните `uv sync --locked`.
3. Для повторной обработки документов с прежней ошибкой `text_limit` выполните:

```bash
uv run --locked legal-workspace reprocess-documents --failed-only
```

4. Запустите один worker и веб-приложение. Прежние оригиналы будут прочитаны заново.

Без `--failed-only` команда поставит на повторную обработку все документы. Она
заменяет прежние задания и извлечённые фрагменты, сохраняя оригиналы и метаданные;
результат старого обработчика не сможет перезаписать новый запуск. Повторная
обработка конкретного пользовательского файла доступна значком повтора при ошибке
или неполном извлечении. Повторный импорт манифеста сам по себе не создаёт эти задания.

Проверки включают PDF на 1000 страниц с полным текстом более 2 млн символов,
граничные случаи 300/301 и 1000/1001 страниц, потоковое сохранение файла 300 МБ,
границу 25 МБ, повторную обработку и отсутствие записей/оригиналов после удаления.
Это проверки на синтетических файлах, а не гарантия разбора любого PDF такого размера.
